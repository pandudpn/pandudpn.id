# pandudpn.id

Pandu Dwi Putra Nugroho's personal site, live at [pandudpn.id](https://pandudpn.id). It looks and behaves like a VS Code window: the CV is a set of files in the explorer, the career history is the Source Control graph, and the terminal answers a handful of commands.

It is a SvelteKit app, rendered on the server by `@sveltejs/adapter-node`. There is no database and no API. Every file shown in the editor is a string in `src/lib/workspace.ts`.

## Run it locally

Needs Node 22.17 or newer.

```sh
npm install
npm run dev      # http://localhost:5173
npm run check    # svelte-check: keep it at 0 errors and 0 warnings
npm run build    # writes build/
npm start        # serves build/ on port 3000; PORT and HOST override it
```

## Where things live

| Path                       | Contents                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------- |
| `src/lib/workspace.ts`     | The files in the explorer and the career graph                                        |
| `src/lib/engine.ts`        | Tokenizers, the Markdown renderer, search, outline symbols, the theme list, terminal paths |
| `src/lib/state.svelte.ts`  | Workbench state and the actions that change it                                        |
| `src/lib/terminal.ts`      | Terminal commands and Tab completion                                                  |
| `src/lib/components/`      | One component per part of the window                                                  |
| `src/lib/icons.ts`         | The codicons the site uses, generated by `npm run icons`                              |
| `src/styles/app.css`       | Layout and components                                                                 |
| `src/styles/themes.css`    | The 13 color themes, 48 tokens each                                                   |
| `src/app.html`             | Document head, plus the script that applies the saved theme before the first paint    |
| `static/`                  | Cascadia Code, the favicon, robots.txt                                                |
| `docker-compose.yml`       | The production containers on the VM                                                   |
| `scripts/deploy.sh`        | `npm run deploy`                                                                      |

## Editing

- Text: change the strings in `src/lib/workspace.ts`. The editor, preview, outline, search, quick open and the terminal's `cat` and `grep` all read from there. Links between files use relative paths, for example `[Klikoo](projects/klikoo.md)`.
- Career graph: each `GRAPH` entry's `find` must appear in `experience.ts`. Clicking the row opens that line.
- Icons: add the codicon's name to `NAMES` in `scripts/build-icons.mjs`, then run `npm run icons`.
- Themes: add a block with all 48 tokens to `themes.css` and an entry to `THEMES` in `src/lib/engine.ts`. Every text color needs a 4.5:1 contrast ratio against the surfaces it sits on.

## Deploy

Production runs on the VM `pandu`, from a checkout of this repo at `/home/pandu/pandudpn.id`. Its `docker-compose.yml` runs two containers on the `tools-net` network: `pandudpn-id` (the stock `node:24-alpine` image) runs `node build` from `site/`, mounted read-only, on port 3000, and `cloudflared-pandudpn-id` forwards pandudpn.id and www.pandudpn.id to `http://pandudpn-id:3000`. The tunnel token is in `.env` next to the compose file. Neither `.env` nor `site/` is in git.

```sh
npm run deploy
```

`scripts/deploy.sh` type-checks and builds, uploads `build/` to `site/next`, swaps it into `site/build`, keeps the build it replaced in `site/previous`, restarts the container and waits until the site answers. If the new build doesn't answer within 30 seconds, the script puts the previous build back, restarts again and exits with an error; the failed build stays in `site/broken`. `DEPLOY_HOST`, `DEPLOY_DIR` and `DEPLOY_CONTAINER` override the SSH host (`pandu`), the directory and the container name (`pandudpn-id`).

To go back to the previous build after a deploy that did succeed:

```sh
ssh pandu 'cd ~/pandudpn.id/site && rm -rf broken && mv build broken && mv previous build && sudo docker restart pandudpn-id'
```

Changes to `docker-compose.yml` reach the VM through git:

```sh
ssh pandu 'cd ~/pandudpn.id && git pull --ff-only && sudo docker compose up -d'
```

### Setting up the VM from scratch

On the VM (the tunnel token is in the Cloudflare Zero Trust dashboard, under the `pandudpn-id` tunnel):

```sh
git clone https://github.com/pandudpn/pandudpn.id.git ~/pandudpn.id
cd ~/pandudpn.id
(umask 077 && echo 'TUNNEL_TOKEN=<token>' > .env)
sudo docker network create tools-net    # skip if it exists
mkdir site
```

Then upload a first build from your machine and start both containers. After that, `npm run deploy` handles every update.

```sh
npm run check && npm run build
rsync -az build/ pandu:pandudpn.id/site/build/
rsync -az package.json pandu:pandudpn.id/site/package.json
ssh pandu 'cd ~/pandudpn.id && sudo docker compose up -d'
```
